# Review Rules for agentic-review

Pick the emphasis below by the paths the change touches; permission and trust boundaries follow `AGENTS.md`.

- **Triggers and snapshots**: when `worker/` or workflow scheduling changes, check delivery deduplication, merging of stale automatic requests, keeping explicit requests, and how repository, base/head, and trigger source pass from dispatch to publication; cover PR updates while queued, comment validation, and failure retries.
- **Coverage and history baselines**: when scope computation or workspace recovery changes, distinguish coverage of the whole PR, PR-level requests, and single threads; check that partial results never advance the complete audit, that failed request scope stays recoverable, and that increments include reverted changes and affected earlier conclusions.
- **Instruction and tool contracts**: when `skills/agentic-review/`, `central/`, or `.github/pi-extensions/` change, check level selection, conditional references, preloading and recovery, tool parameters, and how the final result is actually consumed. When the review protocol reviews its own change, separate this round's pinned control rules from the protocol under review in the target PR; check the public skill's default duties and the central narrowing separately.
- **Platform and runtime**: when replacing Actions, Git operations, or the Pi SDK integration, check that pinned versions, authentication, checkout, and failure semantics are kept, including runner defaults such as the Git LFS filter. For model configuration, preloading, pagination, caching, or retries, trace actual request parameters and context growth; claimed gains must separate plain input, cache reads and writes, model turns, API unit prices, and total latency, judged by how they were measured.
- **Credentials and publication state**: when workflows or the publication chain change, check read/check/publication token isolation; how control code, request identity, and results pass from preparation to trusted publication; and head/run, root comment ownership, partial write failures, rerun deduplication, and completion state.
- **Lark authorization and renewal**: only when the change touches authorization, renewal, or restoring access, check the secret split between `lark-rotation` and `lark-review`, serial consumption of the single-use refresh token, and save-before-publish. When review reading is restored, also check CLI archive pinning, checksums, and credential injection; first authorization follows the actual consumer in the default-branch workflow.
- **Deployment wiring**: when `.github/` changes, read `.github/AGENTS.md`; when configuration, credentials, or runtime dependencies are added, check consumers, trusted preparation, and first-start steps against `docs/deploy-central-review.md`.

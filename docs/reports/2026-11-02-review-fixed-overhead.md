## 本轮变更

发布器第二次 checkout 在这次运行中耗时 1.370 秒，对应 post cleanup 另占 0.222 秒；目标 ref 与 Agent 启动前的控制面版本相同。

准备入口改为从已按固定 `GITHUB_SHA` 检出的可信控制面工作树生成包含 `scripts` 和 `package.json` 的压缩包，将其 Base64 内容保存为步骤输出。Agent 结束后，workflow 的固定启动器从 Runner 保存的输出解包到全新临时目录，再执行发布入口。发布 token 仍在 Agent 结束后签发，请求摘要、覆盖校验、失败恢复、归档和 token 撤销继续执行。

代码包不依赖 Agent 运行后的本地文件或可变 Git 对象；范围恢复和审查结果仍使用既有协议。启动器自身使用默认只读 workflow token，即使发布 token 签发失败，也能先组装可恢复范围。真实代码包的大小通过测试检查，须适合 Linux 单个环境字符串的 128 KiB 平台限制。

本地验证覆盖固定 ref 工作树的文件成员与内容、三类请求、输入准备失败时的代码包交付、本地脚本篡改不参与发布、包缺失或损坏时拒绝启动，以及发布失败的退出状态。完整测试共 159 项通过。真实稀疏部分克隆回归在远端不可用时仍可封存工作树，避免重新引入 `git archive` 的范围外对象懒加载。

## 52 KB 输入为何产生近 48 秒前置工作

[运行 41033016761](https://github.com/Qiyin-Tech/agentic-review/actions/runs/41033016761)已经包含 #93：可信历史工作稿成功恢复，启动时只有三个当前 PR 文件 pending。Agent 仍为 2 分 56 秒、31 轮，总计 3 分 51 秒。

其完整输入为 **605 行、51,951 UTF-8 字节**。生产 `write-review-input.ts` 超过 32 KB 后返回一个短索引，并要求每段读取后先保存结论与进度，禁止一次拼接或并行载入全文。日志前 15 轮约 48 秒，依次读取索引、工作稿、完整输入的五个区间，并反复编辑 notes；随后才开始读 code 层规则。这里包含必要的讨论理解，但逐段写回、尾部核对及再次读取的协调不属于审查语义。

共享根因有两层：材料合并为一个大文件，使一个大评论拖累请求、规则和小 patch 的进入；协议又把工具输出限制变成模型必须执行的分页和记账义务。只把 32 KB 改成某个 Token 阈值，仍保留这一读写状态机，不能解决这个设计问题。

## 本地改造：内容块、Token 预算与原文索引

材料按请求、项目规则、PR 背景、逐文件 patch、完整 thread、普通评论、Review 和恢复清单分别保存。目录记录每块的类别、代码位置、`o200k_base` Token 数及准确原文路径；评论正文保留自然换行，thread 已组装根评论、回复和状态。索引与原文由准备阶段一次生成。

运行时使用 Pi 现有 `before_agent_start` 消息注入能力，按实际模型的 `contextWindow` 和 `maxTokens`，计算可信规则、工具 schema 与材料的初始预算：启动上下文最多占半个窗口，同时扣除最大输出与额外 10% 空间。当前 500K 窗口、128K 最大输出下，启动合计上限为 250K Token。计数使用 Node/WASM `tiktoken@1.0.22` 的 GPT 标准 `o200k_base`，没有 Python 依赖。[OpenAI 编码映射](https://github.com/openai/tiktoken/blob/main/tiktoken/model.py)、[Node bindings](https://github.com/dqbd/tiktoken)。

默认选择顺序来自材料用途：本轮请求和规则、当前比较区间与必要背景、变化的讨论。每块独立考虑；大评论留在索引时，小 patch 和其他相关讨论仍能预载，大 diff 也不会阻断小评论。显式 thread 请求优先该 thread 及其代码位置；automatic 有可信 checkpoint 时优先增量，显式 PR 请求保留计划内各区间，完整 PR 仍在索引中。

相对所恢复快照未变化的讨论默认作为按需参考，原文始终保留。这个标记只表示快照相同，不声称模型已经消费、决定仍适用或问题已解决。模型根据当前范围、契约和疑点选择其余材料；结论依赖的明确决定、相关回复和新鲜度仍须核对。

没有新增读取工具、模型确认回执、持久化游标或逐条消费状态；预载未改变 scope，完整覆盖仍由历史有效调查和本轮调查共同保证。已移除当前 PR 的“先读完全部历史”和逐段落盘义务。固定规则恢复入口已经预填，Agent 再次抄写入口的要求也一并移除。

Tokenizer 依赖按可信控制面的 package/lockfile 缓存，缓存保存安排在 Agent 启动前；Agent 结束后不回写可变目录。这样常规小 PR 不必每次重新下载安装依赖。

## 独立审计仍发现的机械成本

用户明确要求后，单个 subagent 只读审计了生产 `40f6113`，没有修改代码或执行评测。本次已覆盖当前输入的全量历史/分页义务；另外三项仍保留为独立候选：

1. [关联源 PR 完整讨论前置要求](https://github.com/Qiyin-Tech/agentic-review/blob/40f611375b7169c6692f5b24fe27cc8f34a6fd46/central/github-context.md#L83)：一个候选关联源 PR 后，中央要求读整份 PR 全部讨论，共享 known-issues 方法原本只要求足以解释结论的原文和相关回复。可按具体根因、契约或 thread 提供入口，保留相关回复的完整性。
2. [讨论刷新后的 ID 装配](https://github.com/Qiyin-Tech/agentic-review/blob/40f611375b7169c6692f5b24fe27cc8f34a6fd46/central/github-context.md#L33)：覆盖记录、关联 root/reply 和映射删除 thread 属于程序已有信息，当前仍要求模型维护；固定启动基线还会使重复刷新重返累计变化。可由现有脚本生成当前 thread 视图及变化索引，无须新增已消费游标。
3. [compaction 后全册恢复](https://github.com/Qiyin-Tech/agentic-review/blob/40f611375b7169c6692f5b24fe27cc8f34a6fd46/central/review-rules.md#L107)：主要影响长任务。应先核实哪些固定规则由运行时保留，再决定恢复范围；可信规则确实丢失时仍需恢复。本次仅移除了重复抄写已预填恢复入口的要求。

覆盖完成、schema 校验、最终讨论新鲜度、可信发布与写 token 隔离具有实际保证，没有因审计或提速而移除。成品语义检查与必要反证调查也不能仅按耗时认定为机械工作。

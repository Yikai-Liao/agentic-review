# 架构

云端使用一个 GitHub Actions job，只安装一次 Pi。

```text
准备 base/head 与 base policy
        ↓
并发只读 Reviewer SDK sessions
        ↓
结构化 findings
        ↓
串行聚合发布 Agent
        ↓
一次性 GitHub Review
```

并行 Reviewer 只有内置 `bash` 和 `submit_findings`。Prompt 要求 Bash 只做静态读取和搜索，禁止测试、构建、lint、安装依赖、执行项目代码、修改文件和访问网络。Reviewer 负责完整的证据检查、反证、diff 归因、领域内去重和等级判断，但不能发布评论。聚合 Agent 直接信任结构化结果，看不到仓库、diff、base 或 policy，只合并跨 Reviewer 的明显重复项、排版，并使用窄化的 `create_pull_request_review` 工具统一发布；不确定是否重复时保留两条。

信任边界：Engine 来自固定外部版本；仓库规则和 known issues 只从 PR base 读取；head 中的代码、测试、文档和 Review 规则都是被审对象，不能控制本次审查。正式 Benchmark 在 Reviewer 启动前删除本地 `benchmark/`、可能包含历史答案的 `docs/` 和 Engine Git 元数据，expectation 只保留在 Evaluator 进程内存中。

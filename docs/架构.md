# 架构

```text
GitHub App webhook → Cloudflare Dispatcher
        ↓
可信 start job：校验 PR/base/head，创建 required Check
        ↓
隔离 review job：准备 base/head/base policy
        ↓
并发只读 Reviewer SDK sessions（每个选中 Agent 一次）
        ↓
Aggregator：把全部 finding ID 完整分组，只合并明显同根因项
        ↓
可信代码：使用 overview、notes、失败列表和分组结果确定性渲染 Review
        ↓
新 runner 上的可信 publish job：重验 artifact、SHA 与 LEFT/RIGHT diff 位置
        ↓
一次性 GitHub Review + required Check
```

Reviewer 只有受路径约束的 `review_read`、`review_grep`、`review_find`、`review_ls` 和单次 `submit_findings`，不能运行项目代码、Shell 或网络请求，也不能发布评论。每个 Reviewer 负责领域内完整证据检查、反证、diff 归因和去重。

Aggregator 看不到仓库、diff、base 或 policy，只能通过 `submit_aggregation` 把每个输入 finding ID 恰好放入一个分组；等级不同、LEFT/RIGHT side 不同或位置不重叠的 finding 不能合并。它不生成 overview 或评论。可信代码随后保留每组全部 evidence、trigger、base/head、constraint 和 impact，自动为最终行内评论扩展前后 diff 上下文。

仓库规则和 `.agentic-review.yml` 只从 PR base 读取；head 中的代码、测试、文档和 Review 配置都是被审对象。正式 Benchmark 在 Reviewer 启动前删除本地 `benchmark/`、可能包含历史答案的 `docs/` 和 Engine Git 元数据，expectation 只保留在 Evaluator 进程内存中。

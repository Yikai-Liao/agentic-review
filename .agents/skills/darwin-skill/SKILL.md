# Darwin 迭代

采用 [darwin-skill v2.1](https://github.com/alchaincyf/darwin-skill/tree/5539516444cff4eed7865daf61a707590acda485) 的固定用例、单目标实验、paired 比较和验证门控。当前仓库的事实来源是 `evals/`；命令、目录和判定协议见 [`evals/README.md`](../../../evals/README.md)。

## 1. 固定目标与基线

先读当前实验记录，选一个可观察短板，写明改动假设、基线 commit、可变规则、共用上下文、模型/思考级别、用例和 Prompt 字符预算。复用已有用例，并留出不同主题或边界场景验证迁移。期望描述要约束结果与事实，不能把预期答案塞进生成任务。

准备前按 `evals/README.md` 的输入充分性检查逐例写 `input-audit.md`，确认被测阶段、来源、缺口和验收依据。输入缺失先修用例，不能靠改 Prompt 补事实；有意保留的未知只能检验不确定性表达。改变输入后新旧版一起重跑，与旧输入的结果不作单变量提升比较。

用户已授权持续迭代时直接执行；范围、模型成本或外部写入授权发生变化才请求决定。保持当前 PR 和其他未提交工作。实验模型遵循用户限制；未指定时先明确选择，不暗中换模型。

## 2. 一次改一个目标，实际生成

在工作树修改规则，用 `prepare` 冻结基线、候选、共用上下文和用例。Prompt 预算包括全部规则，不把新增要求移进调度消息绕过预算。准备成功才生成；实验已存在则新建轮次，保留失败和被淘汰版本。

按生成任务分别启动全新上下文的 Agent，新旧版使用相同事实、模型、思考级别和重复次数。只做该用例授权的任务；表达评测只生成固定审查事实的文本，不委派开发期代码 Review，不调查或运行目标代码，不向 GitHub 发布。

完成条件：所有输出落在实验目录且来源可追溯。缺输出或执行失败如实记录，不能用手写示例、干跑或挑选最好的一次替代。

## 3. 独立成对评判

生成完整后运行 `blind`，把匿名材料交给 3 个未参与生成、互不知结果的新 Agent；使用同一评判标准，在一次上下文内比较每对文本。按维护者指定使用 sol 评委，逐一记录实际模型/思考级别；luna 可作被测生成器，不作验收评委。新上下文不消除同模型的相关偏差。评委只读取自己的匿名材料，不读取版本映射、源规则、前轮评价或作者结论。输出偏好、是否满足任务及具体缺陷，不以跨评委绝对分数差决定保留。

运行 `check` 检查输入/输出是否漂移、用例/重复/评委是否齐全、规则是否超预算，以及逐例多数意见。亲自复核事实与范围争议，尤其是漏掉问题、静态冒充实测、接受冒充修复或压缩触发条件；不能用多数偏好掩盖已证实的错误。

## 4. 保留、改进或撤回

长度、事实和任务完成门槛都通过，且成对结果支持候选，才提交该改进。结果不充分或仍有失败案例，记录缺陷并按同一目标替换/删减指令后开下一轮；不累加泛泛提醒。撤回仅恢复本轮可变规则，使用可核对 patch 或 revert，保持其他工作。

通过后用新上下文复跑与未用于改写的新案例回归。连续没有实质收益时检查假设、用例和评判标准；尚未满足用户目标时说明并调整方法，而不是将“小幅改善”包装为完成。

完整运行材料写入 Git 忽略的 `evals/experiments/`，失败原文也本地保留；在 `evals/results.tsv` 登记简短决定。Git 只提交可复用工具、用例、标准和精简结果，结果包含代表性前后原文、逐例投票、关键失败/异议及验证边界；不提交逐轮规则副本、派发任务和评判输入。需要跨机器复核时另行共享完整归档，不默认纳入源码。提交/推送按原任务授权，评测命令本身不提交、不发布、不部署。

# 证据获取与执行权限

Review 通过静态只读取证：读取材料并推演结果，不执行代码。本文件说明静态调查边界，以及如何核实已有实测证据。

## 怎样静态调查

读取固定版本的目标、必要依赖、相关历史和获授权提供的原始验证结果。只写本轮私有工作稿或指定报告，不修改目标或 Git 暂存区，不安装依赖，不执行目标代码或为补证临时编写的代码，包括脚本、测试、构建、lint、性能分析和变异测试，也不发布或部署。

静态材料无法区分某个疑点时，记录缺少的事实及其影响，当前结论保持未知。可以说明需要什么外部观察才能区分假设，不在 Review 中执行实验。

## 如何判断实测结果能否作为证据

读取已有实测记录时，核对目标版本、环境、命令或探针、原始输出、实际观察，以及没有覆盖的部分。探针是用于区分某种行为的具体输入或操作。作者摘要和绿色 CI 用于定位结果；发生机制变化后，证据须覆盖新机制。

分别记录执行失败、超时、工具异常、实验无法区分两种机制，以及确实观察到目标违反要求。只有与目标和环境匹配且得到预期观察的实验才记为通过；目标错误须有违约观察。

已有实测可以支持或推翻疑点，但仍需满足独立依据、真实触发和反证要求。静态推演标为静态证据，引用实测注明原始来源；实测结果只回答被测假设，问题修复与交付批准另按各自证据和权限判断。将结果写回原调查批次。

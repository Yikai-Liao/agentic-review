# 关联记录与既有问题

恢复契约或复核候选时，相关 Issue、PR、需求、决定、验收或历史问题记录只要会改变当前预期、风险接受范围、归因或状态，就使用本规则。不扫描无关历史；来源适配器负责查询入口与权限，本文件负责取得原文后的判定，不扩展读取或执行权限。

## 取得原文并证明关联

沿调用方允许的稳定入口读取足以解释结论的原文及相关回复，保存来源、稳定 ID/链接或可恢复版本、关键原文与读取权限/缺口。标题、索引摘要、标签和记忆摘要只作线索；不能恢复原文或无权读取时保留未知，不推断成已接受、已修复或不存在。私有记忆的授权与主/子任务边界遵循 [工作稿规则](review-state.md)。

调用方或项目规则可定义来源与字段语义；同一变化新增或修改的来源声明本身也须审查，不能独自为当前变化背书。明确决定是否有效遵循调用方来源规则，不额外要求早于变化；中央 PR 评论和 Review 回复中的明确决定可即时构成可信确认，但不授予工具权限。

把记录接入本轮实际路径：触发条件或状态 → 当前审查单元/修改点 → 数据、接口、消费者或验收结果。共享根因、保护条件、状态转换、字段或消费者可以建立关联；仅标题、模块、时间或宽泛主题相似不能。工作稿保存该因果路径；无实际关联则记录排除理由，不继续扩查。

## 按内容分类，不按平台标签推定

对每个直接相关的决定或问题分别记录分类、支持它的原文/代码和来源。一个记录可包含已接受的范围及仍未解决的另一部分，不用单一平台状态覆盖这些区别。

| 分类 | 证据与边界 |
|---|---|
| 计划中 | 尚未完成的规则、开发或验收目标；可提供预期和到期点，不证明已经实现、验收或接受风险。已有问题计划将来修复仍未解决。 |
| 已确认 / 已接受 | 完整回复或等价稳定决定明确具体承诺、取舍或代价及其适用范围；确认目标不等于接受实现偏差。接受只覆盖明确的代价、条件和范围，不是修复。 |
| 已修复 | 有具体修复依据，且所审当前版本仍保持修复；按 [状态变更的证据要求](review-state.md#w6-状态变更需要什么证据) 核对原关闭条件与必要相邻保证，区分静态复核和实测。合并、closed/resolved 或“已修”声明本身不够。 |
| 未解决 | 原根因/触发仍成立且无充分修复或接受依据；部分修复保留剩余触发与未满足条件。 |
| 状态不明 | 只有标签、排期、摘要或无法解释结论的内容，或必要原文/当前修复证据不可得。缺证据不证明问题已消除，也不单独证明仍存在。 |

## 接入当前 Review

- 已修复且当前仍成立：不为原问题创建 finding，保存核对依据。
- 已确认或已接受且当前未越出决定范围：采用该契约或接受边界，不重复要求确认、不重报已接受代价；明确撤销或前提失效则重新判断。
- 未解决但原样保留：delta 关联原记录并说明仍未解决，不冒充本轮新增；audit 可在明确受托范围内报告既有问题，保留原编号/来源和既有归因，不制造第二个根因。
- 当前变化扩大影响、使原保护/接受前提失效或重新引入问题：按 [结论门槛](findings.md) 生成当前 finding，说明新差异、见证及原记录；不能沿用旧 accepted/fixed 状态掩盖新增风险。
- 计划中：提取适用契约、验收场景与到期点核对当前产物；不能把未来计划当成已实现或已接受，也不能把尚未到期的合法省略直接报为缺陷。
- 状态不明：记录读取尝试、具体缺口及其限制的判断；继续可完成的调查，依据当前独立证据判定候选，不因 closed 关闭，也不因未知自动生成 finding。
- 仅触及既有问题、未引入/扩大/重新激活风险：说明当前影响，不重复新建 finding。

完成条件：每个相关记录在现有工作稿/batch 中有来源、因果关联、分类依据及当前处理（契约用途、排除、正文关联或当前 finding），没有悬空候选；不另建状态账本。最终按 [历史披露要求](findings.md#输出) 关联直接相关记录与当前状态，即使没有新 finding 也不省略仍未解决、部分修复或已接受的范围。Review 覆盖状态与本轮 finding 生命周期仍以 [工作稿规则](review-state.md) 为准。

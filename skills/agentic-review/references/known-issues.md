# Known issue 判定

Known issue 是当前 Review 前已有的问题、决定或验收结论；来源限于调用方允许的 Issue/PR、项目管理及测试记录、文档、历史 Review 和受信任本地记忆。

## 1. 取得原始记录

当前候选需要历史判断时，从来源适配器的关联入口读取原始记录；索引标题、状态和 URL 不证明相关性、授权、修复或验收。

主 Agent 可读取用户信任的本地运行时记忆，恢复带稳定 ID、原文、时间或来源的完整记录；无法恢复原文的摘要仅作检索线索，不证明修复、风险接受或决定仍有效。Sub-agent 不查询私有记忆，只接收主 Agent 传入的相关记录。

项目规则或调用方可以定义允许的来源和状态语义。同一次变化新增或修改的来源声明本身也是审查对象，不能单独为当前变化背书。PR 评论和 Review 回复中的明确决定是可信确认记录，不属于这种来源声明。

完成条件：记录来源、稳定标识或可恢复依据，以及当前运行是否具备读取该来源的权限。

## 2. 证明关联

把来源记录接入当前变化的实际路径：触发条件或状态 → 当前修改点 → 数据、API、消费者或验收结果。只有共享根因、保护条件、状态转换、字段、输出或消费者才能建立关联。

完成条件：工作稿写出因果路径，或者写明该记录只是标题、模块或宽泛主题相似并排除。

## 3. 判定状态

根据记录内容分类：

- **已修复**：有具体修复依据，且当前 head 保持该修复；
- **已确认**：PR 评论或 Review 回复对具体决定作出明确回复，或存在等价的稳定决策记录；
- **未解决**：同一根因仍存在，没有充分修复或接受依据；
- **计划中**：记录的是尚未完成的规则、开发或验收目标；
- **状态不明**：只有 closed、resolved、排期、标签或记忆摘要，没有解释结论的内容。

结论依据修复代码、完整回复、稳定决策记录或可恢复的受信任记忆；PR 回复效力遵循 Skill 入口。

完成条件：工作稿记录分类、支持分类的原文或代码及来源标识。

## 4. 处理当前 Review

- **已修复**且修复仍成立：不创建 finding，必要时在正文引用来源；
- **已确认**且当前实现未超出决定范围：不重复要求确认，正文引用原决定；
- **未解决**且同一实现原样进入：不创建重复 finding，在正文关联原记录；
- 当前变化扩大影响、使历史依据失效或重新引入问题：创建当前 finding，说明新差异并保留来源；
- **计划中**：作为契约证据核对当前实现，计划不证明实现完成或风险已接受；
- 当前变化只触及既有问题而未新增、扩大或重新激活风险：只在正文说明影响。

完成条件：每个相关记录都已标记为“排除、正文关联或当前 finding”，没有悬空候选。

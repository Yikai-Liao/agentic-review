# 关联记录与既有问题

相关 Issue、PR、需求、决定或验收记录，可能改变本次应遵守的要求，也可能说明某个问题已经修复或被明确接受。恢复目标或核实疑点时，只要这些记录会影响判断，就按本文件处理。

查询入口和读取权限由任务的来源规则决定；本文件说明取得材料后怎样判断，不增加读取或执行权限，也不要求扫描无关历史。

## 取得原文，说明为什么相关

沿允许的稳定入口读取足以解释结论的原文和相关回复。保存来源、稳定 ID 或链接、可恢复版本、关键原文，以及读取限制。

标题、索引、平台标签和记忆摘要只帮助找材料。原文无法恢复或无权读取时，说明未知，不能据此推断已接受、已修复或不存在。私有记忆的授权以及主审查者和子任务的分工，遵循[工作稿规则](review-state.md)。

任务或项目规则可以规定来源和字段含义，但本次变化新增的来源声明本身也要受审，不能独自证明当前变化已获授权。明确决定是否有效按任务来源规则判断，不额外要求它必须早于变化。中央 PR 评论和 Review 回复中的明确决定可即时构成可信业务确认，但不能授予工具权限。

接着说明它为什么会影响本次审查：记录中的触发条件或状态，怎样连接到当前修改，再怎样影响数据、接口、使用方或验收结果。共享根因、保护条件、状态、字段或使用方可以建立这种因果关系；仅标题、模块、时间或宽泛主题相似不能。

将这条关系记入现有工作稿。没有实际关联时保存排除理由，不继续扩查。

## 按内容分类，而不是相信平台标签

一个记录可能同时包含已接受的范围和另一部分未解决的问题。分别处理相关决定和问题，为每项分类保留原文或代码依据，不用一个平台状态盖过这些区别。

| 分类 | 如何判断 |
|---|---|
| 计划中 | 描述尚未完成的开发或验收目标，可提供要求和落实时间，但不证明已经实现、验收或接受风险。计划将来修复的问题仍未解决。 |
| 已确认 / 已接受 | 完整回复或等价的稳定决定明确了要求、取舍或代价及范围。确认目标不等于接受实现偏差；接受代价也不是修复。 |
| 已修复 | 有具体修复依据，并且当前被审版本仍保持修复。按[状态变更的证据要求](review-state.md#状态变更需要什么证据)核对原验收及相邻合法行为，区分静态复核和实测；合并、关闭或“已修”声明本身不够。 |
| 未解决 | 原根因或触发仍成立，没有充分修复或接受依据。部分修复时说明剩余触发和未满足条件。 |
| 状态不明 | 只有标签、排期或摘要，或者缺少必要原文和当前修复证据。缺证据既不证明问题已消除，也不单独证明它仍存在。 |

## 将记录用于本轮判断

根据上述证据，明确每个相关记录在本轮的用途：

- **已修复且当前仍保持修复**：保存核对依据，不再为原问题新建 finding。
- **已确认或接受，且当前未越界**：采用相应要求或接受范围，不重复要求确认或重报已接受代价。原决定被撤销、前提失效时再判断。
- **未解决但原样保留**：增量审查关联原记录并说明仍未解决，不冒称本轮新增。整体审计可在明确受托范围内报告已有问题，但保留原编号、来源和既有归因，不制造第二个根因。
- **当前变化扩大影响、使原保护或接受前提失效，或重新引入问题**：按[结论要求](findings.md)调查新的差异、触发场景和影响，引用原记录；不能用旧的 `accepted` 或 `fixed` 状态掩盖新风险。
- **计划中**：提取适用要求、验收场景和应完成的阶段，用来检查当前产物。既不能把未来计划当作已有机制，也不能把尚未到期的合理省略报为缺陷。
- **状态不明**：记录尝试、缺口及受限判断，继续能够完成的调查。当前疑点按现有独立证据判断，不因平台关闭而关闭，也不因未知而自动报告。
- **仅触及既有问题，没有引入、扩大或重新触发风险**：说明本次影响，不重复新建 finding。

处理完成后，每个相关记录都应在原工作稿或批次中有来源、因果关系、分类依据和本轮用途，例如作为目标依据、排除疑点、在正文关联，或形成当前 finding。不另建一套状态账本。

最终按[历史披露要求](findings.md#输出)关联直接相关的记录及其状态。即使没有新 finding，也不能省略仍未解决、部分修复或已接受的范围。调查覆盖与 finding 生命周期仍按[工作稿规则](review-state.md)处理。

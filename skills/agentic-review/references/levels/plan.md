# Plan：审查从目标到交付的路径

计划不是架构的复印件，也不是写代码的详细程度竞赛；审查它的动作及组合是否足以形成已承诺能力，以及允许经过的中间状态是否成立。共同证据、结论和状态规则由 Skill 入口提供。

## 侧重点与加载

未限定时检查前五项的实际相关部分；明确窄审仅执行所选项及其必要依赖。

| 侧重点 | 方法/特化 | 选择 |
|---|---|---|
| 交付闭合 | [意图对齐](../focuses/alignment.md) + [交付闭合](#交付闭合) | 默认 |
| 依赖与并行可行性 | [依赖与并行可行性](#依赖与并行可行性) | 默认 |
| 过渡状态安全性 | [过渡状态安全性](#过渡状态安全性)；明确失败/中断审计加 [可靠性](../focuses/reliability.md) | 有实际交付边界时 |
| 验收与集成责任 | [验证](../focuses/verification.md) 的错误验收分支 + [验收与集成责任](#验收与集成责任) | 默认 |
| 探索与投入顺序 | [探索与投入顺序](#探索与投入顺序) | 默认 |
| 不必要的协调成本 | [可维护性](../focuses/maintainability.md) | 明确简化/成本审计时 |
| 验证充分性 | [验证](../focuses/verification.md) | 明确保证验证审计或当前验证义务到期时 |

simplify 映射协调成本，不以任务少为目标；harden 映射实际切片的中断/恢复、验收责任与验证充分性。不把计划当实现，不要求每步都运行一次全套测试。

## 恢复计划真正要交付的范围

先读原始目标、有效架构决定、阶段边界和本轮授权，再读任务清单。计划不能自己删减验收目标；但已明确批准的阶段化交付和非目标必须尊重。

登记能力切片、依赖、必要集成、验证义务及过渡条件。不要只登记作者已经列出的任务，否则漏掉的工作永远进不了审查范围。无需固定 tasks.md、任务数量、文件数或上下文百分比。

## 交付闭合

按意图对齐方法对每项受托且当前到期的能力倒推必要状态。本层的特有证据是产生该状态的动作与消费连接：

```text
用户/上层可观察结果 ← 被使用的能力 ← 必要连接 ← 产生该能力的工作
```

找一个全部任务按描述完成、目标仍不成立的具体实例。比如 API 和 UI 分别建好，但计划把接线排除在所有任务之外。不能仅因没有逐字引用需求 ID 就报遗漏；任务描述或共同验收已实际包含该工作时应排除。

明确计划遗漏且没有其他承担者时用 defect；只是任务没有展开内部 helper，而结果和验收清楚，不要求补流水账。

## 依赖与并行可行性

恢复真正的前置条件，不只信 depends_on。检查先使用未提供契约、循环等待、两方各自选择共享格式、多个执行者竞争同一状态。给出最小有问题的允许顺序及后果。

有全局冻结、共同验收或明确集成人员已解决顺序时，不因图上缺一根箭头要求重写计划。文件重叠不是冲突证明，文件不重叠也不是可并行证明。

## 过渡状态安全性

在相关切片结束、部分失败、暂停、回退处检查：保留哪些旧路径、默认开关是什么、新旧双方能否交互、数据可否按承诺恢复。技术方案的最终态正确，不代表迁移顺序安全。

只针对实际交付边界与要求；本地原子修改不强求每一行代码都可独立部署。没有不停机要求时不能发明零停机目标，但必须尊重已有可用性和数据保证。

## 验收与集成责任

使用验证特化的错误验收分支。本层额外核对产生证据的任务、集成观察的责任及到期顺序，不要求现在完成计划中的实验。

所有任务只验证自身产物而无人验证必要连接，可构造“局部均通过、整体失败”的反例。测试命令没有写死不一定是缺陷，行为验收清楚且执行职责已分配就可以。

需要更深验证充分性判断时按本层路由加载验证特化；普通计划 Review 仍可报告具体错误验收或明确遗漏的必要验证任务，不泛化成“测试越多越好”，也不要求用户使用 harden 这个词。

## 探索与投入顺序

读取关键假设及后续投入。合法 spike 应有要回答的问题、可观察结果、结果如何改变后续动作、以及哪个依赖在结论前不能推进。

明确先调查、再决定、再实施的计划，不因为尚无调查结果而判为不可执行。反之，计划已让不可逆迁移或大范围实现依赖未经验证的接口能力，却把调查排在最后，要指出真正的依赖问题。

预算和具体排期由用户约束；不能凭模型估计“太大”硬拆任务。用已知资源冲突、不能并行的前置条件和当前承诺判断。

## 跨尺度反馈

局部依赖/任务遗漏可由计划作者修。实现路径需要改变已批准能力、共享责任、接口或保证时，返回相应架构决定；计划不得用“先做 v1”偷偷删除必须实现的目标。

如果架构本身相互矛盾，保留原始依据和最小矛盾，不能要求计划作者靠更多任务解决不可能的承诺。

## 完成条件

受托目标的交付路径、相关依赖/中间态和验收责任均已调查，对成立、缺失或受限给出结论；候选经过反证并有处理归属。这里要求调查完整，不要求计划已经正确。发现缺少接线或依赖错误也可完成本轮 Review；共同结束规则不由本文件替换。

这里完成的是计划的静态审查，不证明执行后一定成功。返回缺陷/待决项和范围限制，不伪造进度百分比。

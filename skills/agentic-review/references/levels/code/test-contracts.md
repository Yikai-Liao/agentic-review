# 测试审查：判得准，并保留有价值的检测

测试审查检查判定是否符合独立契约，以及能否发现其余测试遗漏的真实错误（**独立检测能力**）。测试数量和表面相似只用于定位调查。

## 选择本次范围和问题类型

增量审查（delta）包含本次修改的测试用例、参数行、断言、测试数据（fixture）、快照（snapshot）、模拟对象（mock）和测试辅助函数（helper）；也包含生产变化使原有错误测试判定重新可达的情况。整体审计（audit）针对明确委托的当前测试集合，报告时注明问题已有，不伪造新增归因。

单纯缺测试、覆盖率或用例保持为调查线索。测试审查报告三种有完整证明的问题：

| 类型 | 要证明什么 |
|---|---|
| **T1：测试失真（false confidence）** | 测试放过了它本来应发现的错误 |
| **T2：测试过约束（change detector）** | 测试拒绝了契约允许的合法变化 |
| **T2：冗余测试信号（zero-marginal）** | 测试可能判得正确，但相对其余测试没有新增错误检测能力，只增加重复失败信号或维护点 |

前两种属于测试有效性，第三种属于测试经济性。完整代码审查按下文变化表选择分支；明确窄审只执行受托分支及其必需证据，其他部分标为范围外。

## 先盘点变化，再按测试含义分组

为范围内每项分配稳定的盘点编号（**census ID**），记录位置、类型、受影响的测试、所属分组和批次。同一测试中每条变化的断言分别登记，完成盘点后再按语义分组。

分组有两个层次：

- **按职责分组（contract family）**：同组测试负责验证同一行为约定，位于相同生产边界和测试层级。替代关系仍由下一层语义特征决定。
- **按语义特征分组（contract fingerprint）**：在上述组内，进一步比较输入类别、边界、生产路径、预期与判定路径、可发现的错误和风险维度。任一项不同就分开，不能因文件或测试名相似归为相同语义。

依赖相同修改前后代码及原始约定的分组，可以放入同一**调查批次（evidence batch）**共享读取结果；批次可以包含多个职责，finding 仍按根因归并。

测试数据、mock 或 helper 可能影响多个分组或批次。每条 `census item → fingerprint` 关联都须有调查结论，共享文件的总状态只用于索引这些关联。

## 为每批建立可比较的证据

增量审查对照 base/head；整体审计比较当前成员与准备保留的测试。只读取所选分支需要的代码和契约，同批各分支复用证据。

职责层共享两个方面：

| 记录字段 | 要说明什么 |
|---|---|
| `contract responsibility / independent source` | 测试负责什么保证，依据为什么独立于待审判定 |
| `focal boundary / test layer` | 真实生产入口、外部边界和单元、集成或契约测试层级 |

每组语义特征还须分别记录：

| 记录字段 | 要说明什么 |
|---|---|
| `partition / boundary role` | 输入按实际生产条件和契约属于哪一类（等价类），是否承担真实边界的检查 |
| `actual path` | 输入怎样经过生产决策和副作用，形成被观察的实际结果 |
| `oracle / verdict path` | 测试如何准备数据、取得预期、执行匹配并决定通过或失败 |
| `failure mode` | 哪类局部错误会被测试发现 |
| `requirement / risk dimension` | 涉及权限、租户、平台、并发或兼容等哪项独立要求 |
| `base / retained representative` | 原有覆盖，或当前准备保留的最小代表 |

**oracle** 是测试判断正确结果的依据，**verdict** 是最终通过或失败的判定。分别追踪实际结果和预期结果，可以发现两者共享错误来源、却仍然相等的情况。

组内每个成员只记录它与共同语义及代表测试的差异，没有差异写 `none`。测试名、变化说明、注释、断言中的值和测试数据用于定位；行为要求和输入边界须来自独立契约与生产机制。

## 先区分真实输入类别，再选择代表

先按实际生产条件和契约划分等价类（partition），再比较具体值：

| 输入 | 应先区分什么 | 通常不足以证明新增检测能力的差异 |
|---|---|---|
| 数值与长度 | 非法下界、恰好边界、内部值、溢出、饱和或精度边界 | 同一内部区间的普通正数，或同一超限类别中的普通长度 |
| 字符串与标识 | 空值、枚举、保留值、非保留值、格式和编码类别 | 同一非保留 key 下替换普通 value |
| 路径与前缀 | 根路径、匹配与不匹配、目录穿越、盘符、平台分隔符 | 相同深度和形状下换普通目录名或文件名 |
| 集合 | 空、单个、多个、重复、乱序、上限和分页边界 | 同一规模和顺序语义下替换普通成员 |
| 状态与身份 | 未认证、角色、租户、归属、前置状态、终态和重试 | 未参与权限、分支或输出的任意名称变化 |

有限的权限、身份或协议集合中，不同成员可能有独立错误风险；集合外的普通值通常属于同一类别。没有分支的公式，也可用输入区分生产表达式或独立契约支持的漏项、错项、比较符、精度或溢出错误。

由生产校验、数据约束或协议确定的边界，有独立检查价值。下界、边界、内部值、上界及上界外按真实分界分别判断，即使当前返回值相同。原来没覆盖的真实边界应直接保留；相邻类别无需另造错误。名字自称“边界”而生产条件和变化前契约没有分界时，仍按普通输入处理。

每组选择原有或最小保留代表，成员只与同组代表比较。符合上方分组差异时先拆组，证据仍可同批读取。

## 根据变化选择要证明的分支

下表说明完整代码审查的必查分支。整体审计按当前受托判定的相应机制选择；窄审只取受托分支。形状触发调查，问题成立仍须相应证明；作用不明的变化先查清机制。

| 变化 | 必查分支 |
|---|---|
| 新增或修改用例、参数行、断言或快照 | 冗余信号；改变实际结果或预期路径时，同时检查失真和过约束 |
| fixture、mock 或 helper 改变真实调用、输入或预期来源 | 测试失真；固定额外判定属性时检查过约束；增加重复判定信号时检查冗余 |
| 预期与生产常量、schema、formatter 或转换共用来源 | 测试失真 |
| 断言固定顺序、完整对象、私有字段、精确诊断或调用形状 | 测试过约束 |
| 生产变化使既有测试的错误判定重新可达 | 测试失真 |

同一语义组共享分支选择结果，成员只分析自身差异。未触发的分支记录 `not applicable` 和理由；受托范围外明确标为范围外，与已完成状态分开。

## 证明 T1：测试放过了应发现的错误

构造一个有独立契约依据、测试本来应拒绝的最小错误，分别追踪：

```text
错误输入或实现 → 生产路径 → 实际结果
错误输入或实现 → 测试准备和预期来源 → 匹配 → 最终判定
```

预期与生产代码共用错误常量、辅助函数或转换，可能使两边同时出错却仍相等；mock 绕过真实权限、事务、持久化或外部副作用，也可能放过错误。须证明当前受托判定使相关测试集合误判，并核实本次变化或审计的归因。

也要检查测试究竟负责哪一层。mock 或 stub 用预设结果替代下层实现，来检查调用方如何传播、映射或展示结果时，测试责任通常止于最近的未替换调用方；下层生产者需要自己的验证依据。

按绕过下层边界调查 T1，须有独立于待审测试的有效约定要求执行真实下层，或者本次变化确实使测试集合失去了独立的真实路径检查。测试名字、预制错误文本或 mock 只用于定位测试责任。

## 证明 T2 过约束：测试拒绝了合法变化

构造一种保持目标契约的现实变化，例如可扩展集合增加合法成员、无序结果改变遍历顺序、对象增加无关字段、内部 helper 等价重构，或逐项调用改为等价批处理。

沿生产结果与测试判定路径，证明测试会失败，并核对没有独立约定要求它固定的属性，才能作为 T2 过约束问题。报告时说明更窄、但仍完整验证行为的判定边界。

## 证明 T2 冗余：删除后不会损失检测能力

先找独立检测能力，再定位重复，最后证明删除不会漏检。找到保留理由即可结束该成员的冗余调查，其他受托的有效性分支仍须完成。

这里只做静态删除分析，不授权修改或运行目标测试。

### 先检查必须保留的理由

沿以下差异查找独立检测能力：

- **行为或边界不同**：真实校验、原来未覆盖的明确边界、权限或归属、状态分支；
- **适用环境不同**：平台、运行环境、编码或外部使用方；
- **验证责任不同**：实际不同的单元、集成、契约测试层级，或独立的判定依据。

静态证明其中任一项提供独立价值，就保留该成员并结束其冗余调查。

例如，契约与生产校验要求 `count <= 100`，已有测试只检查 50，新增测试检查 100。两者当前都成功，但 100 能识别误将 `<=` 写成 `<` 的错误，是应保留的新边界。

### 再定位重复的判定信号

没有上述保留理由时，用以下形态定位冗余疑点，再做删除分析：

- **重复断言**：同一测试观察相同状态、表达式并作相同判定，期间没有修改、await、重试、迭代、时钟推进或有副作用的求值。
- **相同或仅改名的测试**：忽略名称、class 与顶层包装、无语义差异的中间变量后，准备、实际调用、结果、预期和输入作用相同。
- **判定包含关系**：完整对象比较已经包含状态字段，完整集合判定包含相同成员，或原测试已覆盖新增的准备、实际结果和预期。
- **普通数据替换**：只改普通值、名称或局部变量，测试结构、输入类别、生产路径和判定方式相同。
- **重复准备**：准备相同还不够，调用、判定和可发现的错误也相同或已被包含时，才成为冗余疑点。

### 用删除分析检查是否会漏检

对具有共同冗余原因的一组成员做一次分析，不逐成员重复同一份证明。假设移除这些成员，寻找一种真实、局部、违反契约的错误：其余测试仍会通过，被移除的成员却会失败。这样的实例能够证明删除会损失检测能力，需要连起以下依据：

1. 什么错误或行为边界违反了要求；
2. 它怎样经过生产路径影响实际结果；
3. 为什么原有及保留的相关测试仍会通过；
4. 为什么当前成员会失败；
5. 错误来自生产表达式、校验、状态机、外部约定或真实风险，具有独立于待审样本的依据。

反例可来自上述保留理由，以及真实的并发、清理、异常、终态，或生产表达式可推导的漏字段、漏项、错误映射与比较符。名称、普通值或 fixture 描述不同，本身不能证明独立价值。

按具体值、数据表、枚举成员或来源分支区别测试，需要生产代码、当前生产或契约变化，或者独立有效约定中的相应证据。单纯假设实现会硬编码原测试值缺少这种依据；待审测试、断言、预期和同期新增说明只用于定位样本。

删除分析须明确保留集合，每组至少保留能覆盖相应语义的代表。已有代表时比较新增成员；没有旧代表或进行整体审计时，先确定最小保留集合。参数化减少代码重复，检测能力仍由所含语义决定。

### 同时满足以下条件，才报告冗余

1. **有明确的覆盖关系**：该成员的判定已被保留测试包含；或者它与代表的职责、输入类别、边界、生产与判定路径、错误方式及层级相同。
2. **没有独立价值被丢弃**：已核对前述行为边界、环境、测试层级和判定依据等差异，没有成立的保留理由。
3. **删除不会漏检**：已完成对照分析，明确保留集合，没有发现原来能检出、删除后会漏掉的真实错误。
4. **重复有实际成本**：能说明多出的失败信号或维护点。

四项缺一不可；单纯没有找到反例不能代替覆盖关系和完整删除分析。

## 核对变化关系，并按根因归并

每个疑点都记录最有力的合理解释：差异是否实际改变了校验、路径、结果、判定、独立要求或测试层级。值、actor 或测试名的差异须连接到这些语义变化，才能证明独立价值。

增量审查核对旧版是否已有相同误判或冗余，当前怎样引入、扩大或重新触发；整体审计说明当前已有判定与保留集合。都要检查生产 finding 是否已覆盖同一根因。生产问题成立、测试只是同步背书时只报生产问题；测试有独立错误原因时保留 T finding。

冗余问题按共同业务行为、输入类别或边界、判定方式、可发现的错误和测试层级归并，记录为 **cluster key**，即同根因分组的标识。不同生产符号、业务职责或外部边界分别归并；批次、生成方式和“重复原有覆盖”只记录调查来源。

同一根因中的完全复制、改名、普通数据替换、包含关系和重复断言，只作一条 finding 的不同证据。整个测试已冗余、内部又有重复断言时，优先报告整个测试的冗余；若测试本身有独立检测能力，则只报告其中真正重复的断言。

T1 和 T2 过约束属于缺陷，T2 冗余属于改进机会；输出注明具体类型。

## 保存进度并完成本批

沿用现有工作稿，为批次、职责组和语义组保留稳定 ID，并记录上方证据表中的字段及成员差异（`member deltas`）。补齐以下索引与结论，已有证明直接引用：

| 记录 | 内容 |
|---|---|
| `batch ID / status / evidence` | 批次、覆盖状态、所读修改前后代码及独立约定 |
| `coverage` | `census ID → fingerprint` 的全部关联 |
| `branch router` | 所选 `T1 / change-detector / zero-marginal`；不适用记 `not applicable` 及理由 |
| `candidate proof` | 错误接受（`violating`）、合法变化（`allowed`）、删除分析（`deletion`），或 `none` |
| `veto` | 最有力的保留或排除依据 |
| 结论 | 保留、T1、T2 过约束、T2 冗余，或并入生产 finding |
| `cluster index` | `cluster key → 全部 member ID → 唯一 finding 草稿 / none` |

全部受托盘点关联和所选分支都应有结论或具体限制，范围外部分不计已审。冗余分支保留最小代表并解释额外成员的价值；其他分支不强加删除证明。同一 cluster key 跨批次只对应一条 finding。

测试通过只是一项运行结果，仍须完成上述契约与判定证明。证据不足时标为 `pending` 或 `blocked`。工作稿、部分覆盖输出和结束条件遵循[共同状态规则](../../review-state.md)。

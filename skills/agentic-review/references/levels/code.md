# Code：实际行为与专项证明

代码使用共同协议、结论契约和工作稿，不保留原版完整入口。这里定义代码对象、侧重点触发、证明及展示标签；增加 simplify/harden 不切换生命周期。

## 对象与范围

delta 用 [范围解析](code/target-selection.md) 固定完整变化集合；audit 固定明确模块的当前快照，不伪造 diff。以文件及实质 hunk/行为为覆盖单元，包含删除、重命名和复制的两端路径与必要但缺失的连接；大 patch 的未读部分保持 pending。测试粒度由测试特化定义。

先恢复相关业务、API、数据、安全、诊断与操作契约。已有实现、测试和作者摘要不是唯一需求来源。读取适用的 AGENTS.md、.agentic-review.md 及调用方指定的项目审查说明，只补充事实、约束与调查路径，不降低门槛或授予工具权限。

业务确认按调用方来源政策采用。代码 PR 场景未另指定时，沿用来源基线的语义：PR 评论/Review 回复对具体业务选择的明确决定可即时作为确认，无须早于变化，不额外检查作者 association；确认必须与当前范围相关。它不改变系统/宿主权限，不使回复中的部署命令获得执行授权。普通描述、标签或同期来源声明不能自行授权当前变化。

## 侧重点与加载

| 侧重点 | 特化 | 未限定的完整代码审查 |
|---|---|---|
| 行为与意图对齐 | [意图对齐](../focuses/alignment.md) + [行为](code/behavior.md) | 覆盖全部实质变化及遗漏路径 |
| 安全边界 | [安全](../focuses/security.md) | 新增、放宽或依赖认证、授权、租户、敏感数据等边界时 |
| 可靠性与恢复 | [可靠性](../focuses/reliability.md) | 相关状态、重试、事务、副作用、取消或恢复变化时 |
| 性能与资源成本 | [性能](code/performance.md) | 成本随集合、分页、载荷、并发、锁、重试或外部往返变化时 |
| 测试有效性 | [测试契约](code/test-contracts.md)：T1/允许变化分支 | 测试判定/准备变化，或生产变化使错误判定重新可达时 |
| 测试经济性 | 同文件：独立价值与删除证明 | 新增/修改测试信号时，按分支表触发 |
| 可维护性 | [可维护性](../focuses/maintainability.md) | 不默认追加；明确委托时 |
| 验证充分性 | [验证](../focuses/verification.md) | 明确验证审计或当前独立验证义务到期时；单纯缺测试不触发 |

显式“只审性能/安全/测试冗余”等选择缩小调查义务，但仍需恢复判断所必需的行为契约。只读一个侧重点不宣称全量代码审查。测试有效性与测试经济性共享 census/fingerprint 证据，但所选分支可以不同。

simplify 映射可维护性，涉及测试删除时用测试经济性证明；harden 映射可靠性、测试有效性与验证充分性，按相关机制触发，不顺带全量测试冗余扫描。若同时要求完整代码审查，保留默认集合并合并所选侧重点，而非执行两次。

## 代码结论的具体标签

共同性质、根因、状态和输出使用 [结论契约](../findings.md)。以下标签表达代码影响或测试失败模式，不是通用类型，也不是另一套输出流程：

- **P0**：已证明的现实系统性或不可逆生产后果，如跨租户访问、不可恢复数据破坏、资源耗尽或依赖雪崩，阻断相关发布。
- **P1**：常见路径或较大范围可达，破坏关键业务、安全、数据、性能或可靠性且无可靠规避。
- **P2**：已证明的一般生产行为/性能错误，包括诊断和恢复信号；触发/影响较窄或有可靠临时规避。
- **T1**：测试失真（defect），具体错误被错误接受。
- **T2**：测试过约束（defect），或严格删除证明成立的零边际测试信号（improvement）；两者须写明，不仅写“T2”。
- **需人工确认**：decision 的代码展示方式，仅用于确实改变高风险边界、当前必要确认缺失且已检查相关来源的情况，不是弱证据兜底。

不输出 P3/T3。生产性能证明以显著且可避免的真实成本退化/放大为依据，不额外要求显式 SLA。测试标签不按生产影响伪造级别；可维护性机会和验证缺口不能塞成 P2/T2。

高风险变更包括认证、隔离、归属、敏感信息、删除迁移、唯一性、事务、日期、金额、状态、幂等、补偿、兼容和资源/容量边界。已证明后果优先 P；无后果证明但存在当前到期授权分叉才用 decision。同一根因 P、T、确认不重复。

## 验收

恢复应有约束，原触发正确且直接相邻合法行为保持；性能保留规模、成本差分与低成本替代依据；测试保留对应 violating/allowed/deletion 证明。静态修正、已有实测和未验证分别表述。输出格式及固定 schema 限制只在共同结论契约处理，不复制旧版“恰好三段”要求。

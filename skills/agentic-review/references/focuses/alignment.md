# 意图对齐：追踪承诺是否被无授权地改变

用于一个或多个相关层级的意图、范围和目标承接审查。共同协议负责来源独立性、范围与到期义务；本文件负责从依据到产物的对齐见证，不再定义来源权限或状态。

## 共同见证

对当前受托目标找出原始适用条件、必须保持的结果，以及产物如何承接或转化它。取一个依据允许的场景，证明某处丢失、替换、扩大或缩小了承诺；说明是否存在有效授权，而不是只检查需求 ID、标题或关键词。

记录最先失真的转化点及其可观察后果。后续计划、实现和测试彼此一致，不能为前面的无授权缩水背书。反过来，也不能把已经明确批准的新目标按旧目标判错。

| 层级 | 具体调查 |
|---|---|
| 需求 | 用户/场景/范围/例外是否忠实表达原始诉求 |
| 架构 | 目标是否有承担者、机制与必要连接；相关分区是否得到支持 |
| 计划 | 全部任务按描述完成是否形成当前到期能力，是否遗漏集成和消费 |
| 代码 | 现实输入、状态、调用与消费者是否得到承诺结果；使用代码行为证明 |

## 反证与成立

核对有效的阶段范围、明确非目标、已有机制、已分配责任及合法实现自由度。词语不同、未逐字引用、产物不够长，都不是失真证明；未到期实现细节不算遗漏。

例如原始要求执行开始后不受子定义编辑影响，设计只冻结主定义并继续读取可变子定义；若没有其他不变引用机制，编辑后读取会违约。若用户明确仅冻结主定义，则原候选被反证。

具体无授权违约按 defect；下一步依赖尚未确定的范围分叉时按 decision，不能把缺证据伪装成确定缩水。位置绑定最先需要修正的承诺或机制，不按经过几个层级输出几条相同问题。

## 跨层使用

调用方可以直接指定“沿需求到代码检查 X”，也可以只审一个产物。按真实承接关系读取必要层级和证据，共享一条依据链，不为每层启动完整审查；跨层不自动扩大到所有质量属性。

上游变更经过有效决定时更新受影响预期；下游无权自行改变上游承诺。找到首个失真点后仍核对受托链路中是否有独立根因，不能将后续独立错误一律视为同一问题。

关闭是恢复承诺，或取得有范围的有效决定并重新核对相关链路。具体状态使用共同规则；不要求统一所有文档措辞或采用 Reviewer 的方案。

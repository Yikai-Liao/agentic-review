# 安全边界：谁可对什么做什么

用于架构或代码明确的安全审查，以及默认完整审查中新增、放宽或依赖安全边界的变化。需求层用其场景/范围/一致性方法审安全承诺，不把需求描述当实现证明。

恢复主体、身份来源、资源/租户归属、操作、信任边界、敏感数据与允许/禁止结果。依据来自真实消费者、授权契约和有效决定，不虚构攻击者能力或要求全部系统采用同一种安全方案。

## 分层见证

- 架构：参与者都按已给规则工作，但来自较低信任方的身份/权限被直接采纳，或敏感结果跨越没有承担者的边界。
- 代码：现实入口 → 身份与输入转换 → 授权/过滤/执行 → 实际消费者/副作用；具体合法攻击能力使未授权主体得到数据或执行操作。使用 [代码行为证明](../levels/code/behavior.md)，不靠危险函数名定性。

挑战身份替换、跨租户资源引用、过滤后/转换后语义、失败恢复绕过校验、错误信息及日志中的敏感结果。只查与所选边界有因果关系的路径，不因“安全审查”无界扫描整个仓库。

正例：租户来自用户可写请求字段，资源读取未与已认证身份绑定，真实返回路径将他租户数据交给调用者。反例：请求字段只作查询提示，最终服务以可信身份重新校验资源归属；不能仅凭出现 tenant_id 报跨租户。

## 门槛、反证与关闭

defect 需独立安全义务、现实可达能力、越界机制与影响；核对上游认证、下游资源授权、数据转换、部署限制、脱敏和真实消费者。已证明越界不能用“建议确认”降格。

实际改变安全承诺但缺当前必要授权/决定时按 decision 给出最小分叉；采用有范围的有效决定不授予运行或发布权限，也不能忽略更高优先级安全约束。验证覆盖另按受托范围进入 [验证](verification.md)，缺测试不是泄漏证明。

关闭是恢复相关边界，使原越界见证失败而合法访问仍成功；不强制某个中间件。根因已被其他侧重点报告时合并，权限材料不可得则说明受限，不伪造安全认证。

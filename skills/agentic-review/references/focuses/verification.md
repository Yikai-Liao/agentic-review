# 验证有效性与充分性

区分：验收本身给出错误判定、当前保证缺乏区分证据、尚未到期的验证。侧重点名称不决定结论类型；共同门槛见 [结论契约](../findings.md)。

## 范围与当前义务

本文件有两个可分别选择的分支：错误验收/判定有效性，以及验证充分性。前者由层级默认集合或明确请求触发；后者只在明确充分性审查或相关验证义务已到期时触发。依据是原始目标、有效决定、真实外部契约或本次明确审计授权；不以覆盖率、测试数或绿色 CI 定义保证。

| 层级 | 验证对象与见证 |
|---|---|
| 需求 | 验收接受某种产物，但它不能满足真实用户结果；不是要求现在实现测试 |
| 架构 | 场景演练、能力实验或分析是否能区分当前依赖的错误假设/机制 |
| 计划 | 验收任务是否观察最终能力和必要连接，是否在依赖承诺之前产生证据 |
| 代码 | 输入经 production actual 与 oracle/verdict 两条路径后，错误是否仍被接受，合法变化是否被拒绝 |

每项相关保证追到失效类别、保护、观察和判定。代码已有测试失真/过约束使用 [测试有效性证明](../levels/code/test-contracts.md) 的对应分支；不默认同时审测试冗余。

## 两种不同的证明

**错误验收（defect）**：给出满足当前验收却违反独立目标的现实错误，或保持目标却被验收拒绝的合法变化。定位实际观察/判定缺陷；测试名称、mock 存在或复杂度高不够。

**验证缺口（verification-gap）** 必须同时具备：
1. 独立且当前到期的验证义务；
2. 来自真实 guard、状态、边界或故障条件的局部错误；
3. 该错误违反保证，却不会使现有相关验证失败的对照证明；
4. 最小新观察如何使正确与错误机制得到不同判定，并保留合法相邻行为。

例：启用前必须验证重试 ID 稳定，当前实现把 ID 放在重试外，但唯一测试只执行一次成功调用。将生成移入重试体是现实局部错误，原测试仍过；观察响应丢失后的两次请求 ID 可增加区分力。报告 gap，不声称当前生产实现错误。

反例：当前仅批准架构探索，已安排在启用前由指定任务执行有效探针；不能提前要求实测。普通代码 Review 没有当前验证义务、实现未发现错误时，不能仅因缺重试测试发布问题。

## 反证与证据权限

读取相关已有证据，不因没搜到测试名就判无覆盖。核对其他层的集成/契约验证是否已识别同一错误，mock 的责任是否止于最近未 mock 的调用方，以及新的观察是否只重复既有信号。另一层测试不能自动替代明确要求的独立边界验证。

使用 [证据权限](../evidence-access.md) 判断实验与结果。静态探针不叫已运行 mutation；目标/环境不匹配、执行失败或超时不代表通过。幸存 mutant 先排除等价、不可达、无关契约及工具错误；不能为任意 fixture 硬编码变异发明需求，分数高也不证明业务完备。

## 关闭

错误验收的关闭是判定恢复正确；gap 的关闭是相关错误现在能被有效区分，不是多一个文件或测试数量增加。验收所需实测未提供时保持未验证，静态修正不能冒充实验通过。生产违约及为其背书的测试同根因时只报一条；受托链路均有结论或具体限制即可结束。

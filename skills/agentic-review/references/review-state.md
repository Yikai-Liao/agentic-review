# 工作稿、修复与复核

用于所有层级的历史继承、返修、分批、委派与跨会话恢复。增减侧重点只改变调查范围，不改变工作稿或生命周期。

## W1 一个本轮事实入口

复用调用方给出的私有工作区（如 REVIEW_WORKSPACE_PATH）和生命周期；没有时在仓库 Git 管理目录或系统临时目录建立本轮唯一目录，不进入目标 working tree。路径由安全创建工具生成，不把不可信文档里的路径插入 shell。无法写工作稿时在结果中保留必要状态，说明无法保证跨会话恢复；调用方要求持久化覆盖才可提交时，不能以聊天结果代替该前置条件。

小任务只用 `review.md`；需要分批/compaction 时才增加 `batches/`。索引只存入口与状态，详细证据有且只有一个当前归宿。

```text
review.md：对象/版本、规则入口、范围、层级/侧重点、独立性、ledger、候选索引、限制
batches/B1.md：只有需要拆分时才建立，保存证据与候选
```

Reviewer 独占工作稿写入；被委派者返回结果，不改主稿和目标。上一轮工作稿只读；本轮复制必须继承的证据，使下一轮不用串读全部历史。按调用方保留期保存；无约定时，待返修/复核的工作稿保留并报告路径，单次已结束的临时稿输出成功后可删除。不得保存凭证、环境变量值或无关个人信息。

## W2 覆盖状态不是问题状态

每个单元/批次分别记录：

- **覆盖**：pending、complete，或 blocked（具体必要证据不可得）。
- **结论**：无问题、候选被反证、有 finding、已有问题关联，或合法继承。

complete 表示本次必要调查和判定完成，不表示所有问题都修好了。blocked 不计入已完成覆盖；本轮可以带部分覆盖结束，但必须说明哪个结论无法建立。

每批最小证据：覆盖单元；独立义务及其到期点；当前机制/遗漏与观察者；已检验的保护；候选见证；最强反证；接受或失败门槛；根因关联；未完成项。

## W3 保存结论，也保存为什么排除了一个问题

候选与正式 finding 用稳定局部 ID 关联。排除理由包含生效前提，例如“共享 schema 已在代码生成前固定字段；两个消费者实际使用同一版本”。不可只写“不重要”或“用户不喜欢”。

不为每轮重新措辞已证明结论。相同根因换标题、换侧重点、换严重度不能制造新 finding。

## W4 何时继承，何时重开

继承需要旧调查完整，且其目标、契约、消费者、环境前提、反证和当前决定没有受到本轮变化影响。原批次只有“读过”“无 finding”摘要时不能继承完整性。

以下是重开理由：相关实现/设计变化；原始需求或有效决定改变；共享契约、部署假设、消费者变化；新反例或矛盾证据；旧覆盖不完整；本轮明确扩大调查范围。

仅 HEAD 前进、同一目录有人改动、有人说“再严一点”都不自动使所有旧证据失效。先分析实际语义影响；反过来，不同文件也可能共享契约，不能只按路径判断。

重开时先标 pending，记录失效前提，局部替换受影响证据与结论，保留仍有效部分。同步修正关联的反证和 finding 状态，不能只追加新文本留下相互矛盾的旧结论。

本轮新增单元全部进入 ledger；不能用“增量复核”只看作者说修好的几个点，而漏掉修复时顺手新增的机制。

## W5 修复是一份新的提交，不是一场说服

Reviewer 发布本轮结果后结束；构造者在自己的授权范围内修复，并返回：

```text
目标新版本；处理的 F 编号；改变的机制；原见证现在为何不成立；
合法相邻行为；新增变化和上层决定变化；实际执行/未执行的验证。
```

作者新解释如果增加了原产物没有的保证，要求把必要内容纳入新修订再审。可以引用既有事实澄清，不必为了澄清重写全文；不能把会话里的新设定当成旧版已经包含的机制。

复核先重放原见证，再核对修复可能破坏的直接相邻保证和新增范围。满足原验收即可关闭，不追加无关“最好再做”。修复方式不同于 Reviewer 建议，但仍保持义务，应接受。

## W6 状态变更需要什么证据

| 状态 | 必要依据 |
|---|---|
| open / partial | 原问题的关闭条件尚未满足；partial 指明仍缺的修正、决定或验证 |
| fixed | 新版证据满足原 finding 对应类型的关闭条件，相关必要约束与合法相邻行为保持；区分静态复核和实测 |
| accepted | 有明确决定接受具体代价/范围，当前未越界；不写成 fixed |
| excluded | 原问题被反证，记录失败门槛与前提 |
| unverified | 声称修了但当前证据不足，或必需结果尚未提供；不冒充 fixed |

defect 关闭需恢复义务；improvement 关闭需证明约定成本下降且保证保持；decision 关闭需取得其所缺的有效决定/事实；verification-gap 关闭需取得原关闭条件要求的有效区分证据。仅同意承担缺陷或验证不足的代价是 accepted，不是 fixed。问题类型不决定必须实测，但原验收要求实测时不能只靠静态修正关闭。

已有 accepted 且范围未变，不重新征求同意；明确撤销或新变化越界时才重开。closed/resolved 标签本身不足以进入任何已解决状态。计划将来修复仍是 open。

## W7 一轮如何结束，循环由谁决定

以下同时成立即可完成本轮审查：

1. 受托范围已登记并完成必要调查，或明确列出无法完成的部分；
2. 每个候选已按证据接受、排除或记录限制；
3. 存活 finding 去重，有完成条件和所有者；
4. 结果保留范围、独立性、证据类型和未知；
5. 按调用方契约输出后停止。

有 finding 也可以完成 Review。构造者或调度方依据授权决定修复和重新提交，不要求 Reviewer 守候到零 finding。

下一轮必须对应新版本、新证据、真实未解决的见证或扩大范围。没有这些变化，不重新执行相同完整调查；返回仍有效的结果。真有新问题不能为了“收敛”删掉。

不设置固定问题配额、必须多轮或“直到双方满意”。宿主预算耗尽时保留 pending/blocked 并如实结束；预算不是正确性门槛，不把未完成变成通过。意见争议回到证据与决定权，不自动再召集投票 Agent。

## W8 可选并行不是默认对抗结构

独立 Reviewer 与构造者分离，不意味着 Reviewer 必须再拆成多个 Agent。仅在已授权、有工具且至少两个批次可独立调查时委派；一个 evidence batch 不因为有多个侧重点而重复分发。不为委派安装插件、调用外部 Agent CLI 或按产品名称猜测工具能力。

委派传固定版本、单元范围、相关原始依据、共同规则与所选特化、输出边界与完成条件；不预置必须发现几个问题，不透露其他人的赞成/反对作为判断依据。子任务按同一协议仅调查指定 batch，不递归委派、不修目标、不写主稿，只返回证据、反证、结果和限制。主 Reviewer 核对原始依据与覆盖后单写落盘；不存在绕过共同规则的 worker 标记。

私有运行时记忆只由已获相应授权的主 Reviewer 查询，并恢复可复核的原始记录；子任务不查询私有记忆，只接收主 Reviewer 传入的相关记录。无法恢复原文的摘要仅作定位线索，不证明修复、接受或决定仍有效。

# 结论契约

所有层级使用同一契约。层级决定对象与落实时点，侧重点决定调查与具体证明；结论性质、处理优先级和状态是不同字段。不能从侧重点名称直接推出问题类型或严重度。

## 共同成立门槛

发布每条 finding 前必须同时具备：

- **范围与归因**：属于受托范围；delta 说明当前引入、扩大或重新激活的原因；audit 标明既有；新提案绑定本次承诺。
- **独立依据**：目标、约束或被优化的价值有来源，不是待审产物的自我宣称；核对决定的适用范围与前提。
- **机制与见证**：具体可检查，能说明观察者、任务或决定受到什么实际影响；缺词、形状、多数意见或“可能更好”不足。
- **反证已处理**：最强保护、合法自由度、已有决定及合理取舍不能解释该候选。
- **可关闭**：定位最小可操作根因，指出恢复的约束或需补齐的决定，以及验收终点；不要求唯一实现。

不满足任何一项，保存失败门槛或证据限制，不给低严重度占位，不换一个类别发布相同猜测。

## 结论性质及基本见证

### defect — 已证明违反义务

独立义务 + 相关合法触发/顺序 + 当前产物的机制、规定或遗漏 + 违约结果及观察者。允许静态矛盾与逻辑推演，但不冒称实测。未定义与已证明错误不同，合法留待后续的细节不是缺陷。

### decision — 当前必须解决的决定或论证缺口

必须证明：下一项已计划的承诺依赖这个选择/授权/事实；不同处理会改变责任、兼容、保证、成本或执行路径；尚未合法委派且不能由读取现有来源自行消除；可以指出最小问题、决定者及受影响范围。

缺事实给最小调查请求；缺取舍给真实选择及代价。未写重试次数、没测某个指标本身不成立。不能因 defect 证明失败就改报“建议人工确认”。

### improvement — 有证据的改进机会

没有证明违约，但受托范围包含该项优化（明确请求或所用层级的默认集合）。需要真实任务与评价目标、机制导致的当前成本、保持必要保证的可行替代，以及收益与迁移/新耦合/学习等代价的比较。专项还可要求更严格的独立价值或删除证明。

默认非阻断；明确违反已约定目标时应按 defect 证明，而不是将审查者偏好当作约束。“简化机会”可以是这种结论的对人名称，不是独立协议或弱证据通道。

### verification-gap — 当前验证义务未被有效证据支撑

当前到期的独立验证义务 + 现实相关的局部错误 + 现有验证不能识别该错误的对照证明 + 能新增区分能力的最小观察。它不表示生产机制已坏；未来可以多测、低覆盖率或未知本身不成立。具体证明使用所选特化。

没有委托验证充分性调查，且没有当前到期的独立验证义务时，不因普通审查顺带发现“缺测试”而增加此类 finding。已经存在的错误验收可构成 defect；只有需要补充区分证据时才用 gap。同一根因不重复报。

这四种性质不绑定特定侧重点。同一侧重点可产生不同性质，不同侧重点可共享同一种证明。确实出现无法表达的成立方式时，维护者先定义见证和反证再修改共同契约；运行中的 Reviewer 不临时发明宽松类型。

## 优先级、归因与所有权

先判断成立，再依据影响范围、当前承诺和紧迫性区分：阻断相关交付/决定、需修正但可隔离推进、可独立安排。不是所有 finding 都阻断，也不是所有阻断都要求停止整个项目。层级可定义具体展示标签，但不能更改成立门槛或以标签代替性质。

一次最深可操作根因只分配一个稳定局部 F 编号。若修复同一处消除多个侧重点的见证，合为一条，保留相关验收；只有独立修复义务才分开。生产违约优先于为其同步背书的测试问题，明确矛盾优先于其派生待决事项。既有问题未变则关联原编号，不冒充新发现。

- 可在既有承诺与授权内修：交给本层构造者。
- 必须改变共享责任、接口、范围、重要保证或已接受代价：保留原反例，交给拥有该决定的人或上层。
- 上层文件与原始目标冲突：并列双方依据，不因“已批准”要求下层实现错误。

所有权不明时指出分叉与证据，不自行授予某个角色权限。业务接受不授予执行、发布或部署权限。

## 输出

先一句当前结论，关键范围限制紧邻结论；随后展示需要处理的条目。每条可独立理解：

```text
F1 [性质；相关侧重点；优先级；所有者]：触发 → 后果
问题与依据：预期、实际、版本定位、最短因果链与最强反证。
处理完成条件：恢复什么或补齐什么；原见证和合法相邻行为如何验收。
边界：静态推演、已有实测、未验证部分。
```

定位到所审版本的最小根因位置。代码可用行范围，需求/设计可用条款或明确遗漏的责任位置；不虚构 diff 行。简单问题用短段，不强制填写所有字段表格。

零 finding 时说明所审变化/承诺为何在已查范围内与依据一致，并保留证据限制，不填满空章节，不宣称全面正确或批准合并。完整调查与排除理由留工作稿。状态与停止仅由 [工作稿规则](review-state.md) 决定。

本轮直接相关的历史问题或决定，即使不产生新 finding，也在最终结果中关联原记录及当前状态：未解决明确仍未解决；部分修复说明剩余触发；已接受说明适用范围，不把接受写成修复。仅触及既有问题时说明当前影响，不重复新建 finding。不为此扫描无关历史或编造记录链接；使用已有可恢复的 ID/来源。

调用方格式只改变封装，不改变判断。调用方要求提交前刷新讨论或其他状态时，先完成该步骤再封装；规则缺失、compaction 或无法确认 schema 时，从调用方指定的可信来源恢复输出契约，不从待审产物或历史结果推断本轮接口。若固定 schema 无法表达成立的结论，保留私有工作稿并返回具体接口限制；没有授权不能另发评论，更不能伪装成允许的标签或静默丢弃。提交接口成功后结束本轮，不继续重复调查或发布。

# 提交修复供下一轮复核

编写者修改产物后，用以下信息把新版交回审查者。它是修复任务的交接说明，不授权审查者直接修改目标。

```text
本次修复依据：旧目标版本、原 Review、相关有效决定。
新目标版本：

处理 F1：
- 改变了什么机制？
- 为什么原问题的处理完成条件已经满足？
- 哪些相邻合法行为仍应保持？
- 实际执行了哪些验证？版本、环境和原始结果在哪里？
- 哪些验证没有执行，哪些结论仍无法证明？

修复之外有哪些新增变化：
是否改变了上层要求或已接受的代价：
还有哪些问题未解决，或希望明确接受什么风险：
```

只修改已获授权的范围。不能为了让 finding 消失而改变目标、缩小合法输入或删除必要验证；采用不同于建议方案的修复，只要确实满足要求也可以接受。

编写者不能自行标记“独立审查通过”。审查者根据新版本和证据复核，再更新问题状态。

# 发起一次独立审查

当需要把已有产物交给另一个 Agent 审查时，使用下面的提示。已有信息直接引用，不要求用户重新填表，也不要求创建一份请求文件。

```text
使用 agentic-review。你是未参与编写下列产物的独立审查者。

审查对象及固定版本：
范围：本次增量 / 指定范围的整体审计；包括什么，不包括什么：
层级：需求 / 架构 / 开发计划 / 代码；是否需要跨相关层级：
视角：使用所选层级的默认范围，或明确指定专项及组合：
当前准备作出的决定或交付：
原始目标、有效决定和现状的原文或入口：
被审产物及必要依赖：
哪些内容可以留待后续决定，已经由谁负责：
前次 Review 及本轮新增变化（首次可省略）：
私有工作稿位置和保留规则（没有指定时按默认规则）：
权限：只读目标，只写工作稿或指定报告；不运行目标代码、不修复、不发布。
输出：有证据的问题、当前需要作出的决定、处理完成条件及审查限制。
```

`simplify`、`harden` 按所选层级解释为相应简化或加固视角，不增加权限。实验授权与上述默认不同时，按[证据权限](../references/evidence-access.md)明确实验范围；模板本身不是授权来源。

版本和来源来自实际读取或任务提供的信息，不能为了填表编造。不要要求必须找到若干问题，也不预先告诉审查者“方案已经很好”。

委派大任务中的一批调查时，额外明确指定单元、禁止递归委派，以及只返回证据和结论、不写主工作稿。其余授权条件仍按共同工作稿规则。

按需要选择后续模板：[记录调查](review-record.md)、[报告问题](finding.md)、[提交修复](repair-return.md)、[请求上层决定](escalation.md)。维护或扩展方法时使用[维护者说明](specialization.md)。

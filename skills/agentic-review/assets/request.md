# 独立审查请求（调用方 → Reviewer）

可直接作为委派提示，不要求创建此文件。不要给 Reviewer “必须找到 N 个问题”或“方案已经很好”的结论。

```text
使用 agentic-review。你是未参与下列产物构造的独立 Reviewer。

对象与固定版本：
范围：本次增量 / 明确整体审计；包含与排除：
层级：需求 / 架构 / 计划 / 代码；可以跨相关层级。
侧重点：使用层级默认集合，或明确指定窄审/组合（含 simplify / harden 别名）。
当前要作出的承诺或交付：
原始目标、有效决定、相关现状的原文/入口：
被审产物及必要依赖入口：
仍可自由选择或已合法委派的部分：
之前的 Review 与当前新增变化（首次可省略）：
工作稿位置及保留规则（没有时使用默认私有路径）：
授权：只读目标；只写工作稿/指定报告；不运行目标代码，不修复、不发布。
输出：只给符合门槛的问题、具体待决项、验收条件和范围限制。
```

实验授权如不同于上述默认，使用 [证据权限](../references/evidence-access.md) 明确范围；模板本身不授予权限。按需使用 [工作稿](review-record.md)、[问题卡](finding.md)、[修复返回](repair-return.md)、[向上反馈](escalation.md)，新增特化见 [维护者模板](specialization.md)。

已有信息直接引用，不让用户重填。版本与来源必须由实际读取或调用方提供，不能为了填表编造。大任务委派给 batch Worker 时额外标明仅审指定单元、禁止递归委派、只返回证据与结论不写主稿。

# 报告一个有依据的问题

按[结论要求](../references/findings.md)确认成立后，用以下字段组织能独立读懂的问题条目。简单问题用短段即可，字段按需选用。

```text
F1 [性质；相关视角；处理优先级或代码标签；处理者]：触发条件与后果

问题：什么情况下，应当得到什么结果，实际却怎样？
依据：所审版本与位置；独立要求从哪里来；错误怎样发生？
已检查的合理解释：为什么已有保护、决定或允许的实现选择不能排除它？
处理完成条件：需要恢复什么要求或补齐什么决定？不强制唯一方案。
如何复核：原触发应得到什么结果？哪些直接相关的正常行为仍应保持？
证据限制：哪些是静态推演、已有实测或尚待验证？是否需要上层决定？
```

代码标签按[代码层定义](../references/levels/code.md#用标签说明已经证明的影响)使用，已表达优先级时省略重复文字；问题性质和处理状态仍分别记录。

`open`、`partial`、`fixed`、`accepted` 等处理状态使用任务指定的结果记录；没有独立结果存储时保存在[工作稿的正式问题](review-record.md#正式问题)。依据见[状态变更规则](../references/review-state.md#状态变更需要什么证据)。新 finding 的公开字段沿用任务指定格式；报告历史问题或复核结果时，按实际状态说明处理进展。

改进机会额外说明真实任务、可行替代和迁移代价；验证缺口说明哪种局部错误无法被旧验证发现，以及需要新增什么观察；待决事项说明为什么当前就需要这个答案。

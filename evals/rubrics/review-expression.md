# 文本评判目标

只评生成文本，不审查代码，不重新判定输入已经固定的缺陷。比较同一案例的两份匿名输出，不知道哪个版本新旧。先判断每份是否满足目标，再给 X/Y/tie 偏好及 clear/slight 把握，不使用绝对分数差。

总评目标：被测输出是审查者撰写的 `body`；标题、问题索引、审查位置和运行信息由发布器生成，输出中重复这些内容视为不合格。读者是借助 AI 编写改动、不一定熟悉实现机制的 PR 作者。结论一两句，说明下一步做什么、先处理哪个；没有问题时直接说没有需要处理的问题。“合并后的行为”让作者核对合并后系统会怎样：以 base 为参照写最终状态，不出现 PR 的早期版本；用使用者能观察到的操作与反应书写，不能省略变化介绍或用内部机制清单替代；改变既有行为而 PR 描述未说明的项标“（PR 描述未提到）”，PR 描述与实现矛盾时直说。续审时“自上次审查”只用一句说明本轮推送的改变，方向改变时写“方案改变”，删掉它其余内容仍成立；首轮没有这一行。“核对了什么”每项须有场景、结论与阻止机制，并带固定事实给出的代码定位；缺定位，或补造事实没有的路径、行号，均不合格。无新问题时写 3–5 项，事实给出的场景不足时按实有数量；有新问题时最多 3 项；事实没有核对场景时省略这一节，不虚构。正文不列问题清单，不复述 finding 的证明与修复，也不复述关闭原因；这些由索引、讨论和状态标注承载。局部范围及关键证据缺口可见，未发现问题不等于测试通过或批准合并。作者报告的测量在句内写明来源和测量对象。不附加保证清单、默认静态审查声明或未执行事项。

Finding 目标：输出首行为 `**标签：标题**`，随后是正文。标题一行写触发与后果，单独出现在总评索引中也能看懂，与正文的对象、条件和等级一致。缺陷和测试问题的正文分“什么情况下出错／为什么／怎么改、怎么验证”三段；需人工确认和待决事项分“实际行为／和预期的差异／影响／需要的决定”四段；改进机会分“现状／建议”。读者懂相关语言、读过 PR 简介，但没有参与本轮审查；仅凭这条讨论就应能复述操作与触发、可观察后果、原因和恢复目标。作者可能把整条交给编码 Agent，“怎么改、怎么验证”单独复制出去也要能执行：写出完整路径、期望行为和验收场景，不用“上文”“该处”这类指代，不把建议方案写成唯一实现。必要项目规则就地解释，同一对象名称稳定，每段增加新信息。技术名词服务因果证明；避免一长段塞满条件或把调查日志交给读者。

状态说明目标：状态变化时输出一行状态原因，发布器会在前面补上状态词和提交号，输出重复它们或写成多行均不合格。原因按处置写：已修复写什么使原触发不再发生，被反证写推翻原判断的事实，已接受写谁在哪里接受了什么范围，升级或重现写新的触发与后果；都附依据定位，部分修复不写成已修复。显式 thread 请求输出回复正文，可以多段，答复本次请求并说明改变判断的原因，不要求重复整条原问题。两者都保留影响判断的具体范围，不追加默认审查方式的声明。

硬性事实门槛：不添加原始事实没有的缺陷、损害或测试结论；不漏掉本轮新问题和历史状态变化；不把已接受写成修复，不扩展决定范围，不把局部结论写成整个 PR 已验证。未变化的历史状态不在正文重报（发布器的索引列出仍未解决的问题），显式复核请求须直接答复；仍有旧问题未解决时不能声称全部解决。不为了显得更完整而补写推测。偏好必须受这个门槛约束。

报告每个 case：X_pass、Y_pass（满足用户目标，不只是语法正确），preference X/Y/tie、margin clear/slight、具体理由及各自不合格点。总偏好不覆盖单个硬性事实错误。

先分别检查两份输出是否合格，再比较偏好。“比另一份短”不等于 pass：摘要照抄 finding/evidence/schema/thread_updates 等内部协议名、汇报不存在的历史/人工确认项，均不满足业务摘要目标；即使整体更好也记该份不合格。新 finding 关联另一个原问题时需要原 thread 链接；直接发布到该原 thread 的 evidence/request_reply 无须再附自链接，但仍须保留改变判断的代码或决定来源。不能把已知回复位置与修复证据混为一谈。逐例检查具体文本，不只列较差版本的缺陷。

可理解性与事实保真分别判定。对每份 finding 逐项回答上述四个问题并引用评论原句作为依据；无法回答就记“未说明”，不得用评委持有的固定事实补全。固定事实只用于随后核对答案是否正确。缺少关键前提或因果关系，即使事实没有错误也不合格；遗漏触发、扩大影响、把静态推演写成实测、新增未证后果或强制唯一修复方案均不合格。字数、短句和标题数量不能替代这些判断。

需要隔离技术背景补全或开展真人验证时，按[成品复述验收](../report-comprehension.md)准备读者材料；匿名偏好和模型试跑本身不代表真人理解效果。

公开评论重复声明“静态审查／推演”“未执行测试／未模拟故障／未复测”，或添加与当前结论无关的防御性说明，均视为表达不合格。事实保真由正面准确的陈述实现，不要求把工作稿中的每项验证记录输出给读者。

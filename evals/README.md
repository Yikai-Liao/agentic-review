# Review 的 Darwin 迭代

这是维护工作流，不是另一套生产 Review。固定事实的表达用例不能证明缺陷识别准确率；审查逻辑优化需另加带独立缺陷真值的用例。当前支持总评、新 finding 和历史 thread 回复。

先看[本次真实结果与前后文本](RESULTS.md)，简短历史在 `results.tsv`。完整运行材料在本地 `experiments/`，由 Git 忽略；全新克隆不包含历史运行产物。

## 一轮实验

1. 在 `cases/` 保存固定输入，在 `rubrics/` 维护独立验收标准；在 `experiments/<id>/experiment.json` 写一个改动假设，按下节逐例完成 `input-audit.md`。
2. 修改候选规则，运行 `pnpm eval:prepare <id>`。它从明确的基线 commit 读取可变规则，从当前工作树读取候选；共用上下文只读取一次。用例、规则和 hashes 固定在该实验里，已有实验不能覆盖。
3. 使用生成的 `generation.md` 分别派发新旧版与重复轮次，模型和思考级别按实验声明。输出写到指定路径，不把基线结果或理想答案交给候选生成器。
4. 输出齐全后运行 `pnpm eval:blind <id>`，分别把 `judges/1.md`、`2.md`、`3.md` 交给三个新的 sol 评委上下文，记录各自实际模型/思考级别。每份材料都包含相同事实和匿名 X/Y 输出，顺序交错；评委只读自己的材料。luna 是被测生成器，不是验收评委。上下文隔离不消除同模型的相关偏差，多数偏好不是客观真值。
5. 运行 `pnpm eval:check <id>`。规则、输出或评判发生漂移、缺项、超预算时失败；逐例至少两票认为候选满足目标，且候选整体至少获两票优于基线，才建议保留。平局不足以证明改进。合格案例仍可略微偏好旧版，逐例偏好与异议照实保留；不要求每例都胜过基线。事实错误须人工复核，不以多数票掩盖。
6. 在 `results.tsv` 登记真实决定；完整原文和失败记录本地留存。达标后再做新上下文重复与新主题回归；提交规则、工具、去重用例与精简结果，不提交运行目录。结果保留代表性新旧原文、逐例投票、关键失败/异议及边界；跨机器复核需要另行共享完整归档。

Agent 的派发与模型调用使用现有运行时工具，命令只处理本地材料；没有模型 SDK、后台服务、自动提交或 GitHub 写操作。禁止用表达评测授权执行目标 PR 代码。内部工作流入口是 [darwin-skill](../.agents/skills/darwin-skill/SKILL.md)。

## 先检查输入，再归因 Prompt

`input-audit.md` 记录逐例的原始来源、被测阶段、必要事实是否齐全、刻意保留的未知，以及每项验收在输入中的依据。命令要求有非空审计记录并冻结 hash，但不把“文件存在”当作语义审计通过；维护者仍须阅读原始输入。审计和期望答案不交给生成器。

| 被测输出 | 输入至少应提供 |
| --- | --- |
| 总评 | PR 目的、实际范围、结论与支撑依据、全部问题的定级/定位、历史问题及最新处置、证据和执行边界 |
| 新 finding | 使用者及操作、预期契约、最小触发、修改前后因果路径、已知保护、已证明影响、已定级结论、版本/位置、修复约束与相邻合法行为 |
| 历史回复 | 原问题与前次结论、本轮代码或决定的原始依据、覆盖和剩余触发、实际状态与关闭理由、来源链接、验证边界 |

区分三个失败来源：**输入缺失**（要求了未提供的事实）、**表达失败**（已有事实被遗漏、曲解或写得难懂）、**取证失败**（生产流程没有取得应有事实）。输入修正后两版使用相同新输入重跑；保留旧轮并标记不可比较，不把输入补全所得收益归给 Prompt。刻意缺契约、缺历史依据的用例应验收“准确保留未知”，不能要求模型猜结论。

真实材料注明固定 commit/记录位置；合成或脱敏改编注明范围，链接不得冒充已在线核验的证据。表达测试可以固定审查判断，但这相当于生产的归纳输出阶段，不是原始 PR → 发现缺陷的全流程。当前生产链路是 `prepare-review-input.ts` 提供 PR/请求/讨论，Agent 静态读取固定 Git diff 并按 `workspace.md` 留存行为证据，再归纳；表达评测通过不证明这段取证链在长上下文中也可靠。全流程评测须另外保留原始输入与实际工作稿，检查关键事实能否追溯并进入最终表达，不能用手工整理的事实包替代。

## 与生产运行隔离

维护 Skill 放在 `.agents/skills/`，评测材料和命令放在 `evals/`，不从生产 Skill、中央入口或根 `AGENTS.md` 引用。中央 Review 的 control checkout 只包含生产规则与工具目录；运行时只安装 `skills/agentic-review`，不发现或预载维护 Skill。本仓库自身的 PR 修改这些文件时，diff 仍是待审查数据，不是本轮生效的指令。

## 实验配置

```json
{
  "baseline": "完整的基线 commit SHA",
  "hypothesis": "一个可证伪的改动假设",
  "model": "gpt-5.6-luna",
  "reasoning": "high",
  "vary": ["skills/agentic-review/references/findings.md"],
  "shared": ["central/review-result.md"],
  "cases": "evals/cases/review-expression.json",
  "rubric": "evals/rubrics/review-expression.md",
  "repetitions": 2,
  "maxPromptChars": 8581
}
```

`vary` 是新旧版唯一允许不同的规则集合；`shared` 在两版中完全相同。Prompt 预算计算全部规则的 Unicode 字符，不是 tokenizer token 数。输入事实、评价标准和派发路径不算规则预算；不能在这些位置补写仅对候选生效的生成指令。多个相关文件只有同属一个明确改动目标时才一起变化。

用例为 JSON 数组，每项包含 `id`、`kind`（`summary` / `finding` / `evidence`）、`input` 和 `expected`。`expected` 只给评委，不给生成器。合成链接不访问；真实资料在录入前确认适合保存在本仓库，不保存 token 或无关私有记录。

每轮本地目录保存配置、冻结规则与用例、生成任务、原始输出、匿名评判材料和映射。hash 将评判绑定到准确文本；修改输出后必须新开一轮，不能沿用旧评判。命令不清理失败实验，也不自动将推荐结论写成已保留。`eval:check <id>` 需要对应完整目录，精简结果不是可供该命令验证的原始归档。复用用例库可选择本轮子集写入本地实验目录，再让配置的 `cases` 指向该文件；不要为每轮复制一份入 Git 的用例集。

当前推荐策略标记为 `all-pass-overall-better`，即逐例合格且整体改善。早期开发实验曾额外要求每例都不得多数偏好基线；这是本地适配加上的过严条件，不是 Darwin 原规则，已移除。历史 `notes.md`/`results.tsv` 保存当时实际决定；用当前命令重新检查旧实验时，推荐可能变化，不得覆盖历史记录或把新推荐写成当时已通过。生成、评委、事实标准和原文不因该策略修正而改写。

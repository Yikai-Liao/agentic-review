## 父会话复核与代表性原文

以下是父会话逐例核对输入、输出和争议后的判断，不是实际读者测试，也不是第四位匿名评委。

### B01：评分差异受合成环境限制，不能直接归因于改写

基线：

> 原因是 `input.md` 仅说明“目标设计可读取”，未提供目标设计正文、路径、版本或可核对的直接依赖；当前目录中没有该设计材料。

候选：

> 本轮**不能形成独立审查结论**，也不能据此宣称目标设计通过或无问题。

两版都拒绝冒充独立审查。候选把主要原因限定为作者上下文与独立性限制；基线首先要求补齐设计。按题面“目标设计可读取”，三位评委均判基线增加了不成立的阻断条件。但实际隔离目录确实没有另一份设计正文，只有这句合成前提；候选末尾也写了“没有设计内容、版本或实测证据可用于本轮独立判断”。因此本例不能证明候选独立性能力提高，更不能将基线表现直接认定为实际环境中的捏造。若要消除该干扰，应给两版相同可读设计后重新比较；本轮未改输入或重跑。

### C01：候选把已有成本关系写得更明确

基线：

> 使实际常见的 10000 个 ID 从 10 次远端请求增至 10000 次；同步路径需等待全部结果，远程往返至少放大 1000 倍。

候选：

> 成本模型：设 N=10000、批大小 B=1000。base 调用次数为 `ceil(N/B)=10`，head 调用次数为 `N=10000`，远端调用数放大 `1000` 倍。

两版都正确说明规模、等价批处理替代和静态边界。三位评委偏好候选的显式模型及分组，但正文由 550 增至 962 字符；这是表达收益与长度代价，不是新发现了基线漏掉的性能缺陷。

### P01、C09：基线有值得保留的局部表达

P01 基线直接展开所需链路：

> 点击按钮 → 网页消费导出能力 → 调用 API 并处理文件结果

候选同样发现缺少调用路径，但基线对接线、文件结果处理及最终验收的展开更直接。评委 1、3 还将候选提到 `control/` 规则视为无依据来源；这一批评不成立，生成器实际获准读取这些方法规则。保留原票，但不采纳这部分理由。

C09 基线把证据方式放在具体状态旁：

> **P23（已修复，静态复核）**

候选写成：

> **P23：已修复且保持。**

候选在报告末尾统一说明仅依据静态材料，并未冒充实测；基线的就地限定仍更容易理解。这是两位评委偏好基线的有效理由。

其余用例未发现足以推翻原始通过评分的事实争议。C05 的“过约束”比 `change-detector` 更直白、C10 对输入已确定的旧值结果不再写“可能”，各获一票偏好；没有扩大为稳定收益结论。

## 轨迹与完整性检查

**通过的检查：** 27 份输出齐全；三位评委各覆盖恰好 12 例；冻结规则、各生成目录的输入与规则、独立预期和评判材料均未漂移；评判的输入、预期与输出转换可追溯；生成器没有读取另一版本、gold 或其他用例，也没有运行目标代码。当前候选与冻结版本一致。

**未通过的检查：** 严格匿名材料边界。评委 2、3 均在写出评分后调用 `git diff --cached --quiet` 检查暂存状态。评委 3 首次在无 Git 仓库的临时目录执行失败，随后以 `git -C` 指向本仓库成功；共三次 Git 检查。成功调用没有输出，失败调用返回 Git 用法，没有源规则、diff 正文或匿名映射内容。评分文件没有因此重写，但这些调用超出了评判所需材料，不能追认成完全合规。

轨迹还包括评委对自己输出的 JSON 语法检查，以及两个生成器回读自己指定的报告；这些是产物自检，不是读取另一版本。初次工具白名单检查将它们和 `control/**` 内查找入口一起列为异常；逐项核对后移除误报，保留上述 Git 偏差。初次审计结果也已归档，没有覆盖删除。

原始生成报告可能带运行时附加的 `acceptance-report`；传给评委的文本由运行时去掉该块，再附加不暴露版本的输出路径提示。已从评委会话还原实际匿名材料，核对它与保存原文的这一转换完全一致。长度统计单列净正文，不拿原始文件大小混算；这次传输仍带有框架包装，不等同于生产发布文本。

分析脚本保留 `strictProtocolPassed: false` 并退出非零，不用“任务完成”或多数评分掩盖协议失败。本轮不满足 Darwin 的“逐例合格且整体改善”保留门槛，也没有取得无瑕疵的三评委盲评证据。
